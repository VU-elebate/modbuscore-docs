Build

cmake -S . -B build/ -D CMAKE_BUILD_TYPE=Debug
cmake --build build/

For Release: replace Debug with Release. The Debug build adds -Wall -Wextra -lpthread.

CMake options (all have defaults):

Option Default Description
MODBUS_TESTS ON Build Google Test suite
MODBUS_COMMUNICATION ON Build the communication layer
MODBUS_EXAMPLE OFF Build example programs

./build/tests/Debug/modbusCore_tst # Linux
./build/tests/Debug/modbusCore_tst.exe # Windows

Run a single test with ‘--gtest_filter='SuiteName.TestName’`.

Architecture

Device<T> is a CRTP base class — T is either Server or Client. Template instantiations are explicit and live in src/device.cpp, not in headers. Adding a new Device specialization requires updating device.cpp.

Four Modbus memory blocks (all behind mutexes):

  • Discrete Inputs — read-only 1-bit values
  • Coils — read-write 1-bit values
  • Input Registers — read-only 16-bit values
  • Holding Registers — read-write 16-bit values

Communication is an abstract base class for transport layers (TCP/IP, Serial). New transport layers must implement readData and writeData.

Code style

  • Namespace: ModbusCore
  • Classes: PascalCase; methods: camelCase; private/protected members: _prefixedWithUnderscore
  • Doxygen /** */ comments on all public API
  • No .clang-format config exists — match the style of surrounding code

Cross-platform

The library targets both Linux and Windows. WinSock2 references in tests are transitional — do not extend Windows-only socket code. New code should use platform-agnostic abstractions or #ifdef guards.
